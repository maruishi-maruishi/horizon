# Horizon 独自セーブ形式（hzr）仕様

自分用サーバー向けの、バニラの Anvil（`.mca`）に代わるチャンク保存形式です。`crates/horizon-world` の `hzr.rs`（ホット層）、`archive.rs`（コールド層）、`ecc.rs`（誤り訂正）、`tiered.rs`（2層の切り替え）、`region_convert.rs`（変換と検査）で実装しています。

## 決めたこと（2026-11-11）

| 項目 | 決定 |
| --- | --- |
| ファイルの分け方 | ディメンションごとの本体アーカイブ（コールド層）と、使われそうなチャンク用の一時リージョン（ホット層）の2段 |
| 地形・エンティティ・poi | バニラ同様、別々に保存（`region/` `entities/` `poi/` それぞれに2段構成） |
| 破損対策 | QR コードと同じ Reed–Solomon 符号で、コールド層のデータを復元できるようにする |
| 圧縮 | zstd。ホット層はレベル3（書き込み速度優先）、コールド層は高めのレベルと学習した辞書 |
| 変更チャンクだけ保存 | 中身が前回と同じチャンクは書かない |
| 破損チェック | ワールド全体を検査し、直せるものは直すコマンド |
| 移行 | 別の変換ツールで `.mca` との間を往復する。サーバーは移行機能を持たない |
| 新しいワールド | 専用サーバーが新しく作るワールドは、最初から hzr（2026-11-12 追加） |
| バックアップ | 今回は作らない。後でプラグインで作れるよう、チャンクごとの世代番号とチェックサムを残す |

## ワールドの見分け方

ワールドフォルダ（`level.dat` のあるフォルダ）に `horizon-storage.json` があれば hzr 形式です。

```json
{ "format": "hzr", "version": 1, "settle_after_seconds": 600 }
```

なければ、バニラの `.mca` として読み書きします。既存のワールドの形式は、サーバーは変えません。変換ツールだけが、このファイルを作ったり消したりします。

**新しいワールドは最初から hzr（2026-11-12 追加）**: 専用サーバーが `level.dat` のないワールドを新しく作るとき、フォルダに `.mca` が1つもなければ、このファイルを書いてから生成を始めます（ログに `New world: saving in Horizon storage (hzr)` と出ます）。変換は伴いません。手で `.mca` を置いたフォルダはそのままバニラ形式です。バニラ形式で新しく作りたいときは、ワールドができたあとにサーバーを止めて `convert-world <ワールド> mca` を実行します。

## 2段構成

各ディメンションの `region/` `entities/` `poi/` フォルダに、それぞれ次の2つが入ります。

```
region/
  r.0.0.hzr  r.-1.0.hzr ...   ホット層: 最近書かれたリージョン
  archive.hza                  コールド層: それ以外の全チャンク
```

- **読み込み**: ホット層、コールド層の順に探す。ホット層の「削除済み」記録は、コールド層の古いコピーを隠す。
- **書き込み**: 常にホット層。コールド層のコピーは、次にそのリージョンが沈むときに置き換わる。
- **沈める（ホット層からコールド層へ）**: リージョンに `settle_after_seconds`（既定 600 秒）書き込みがなければ、バックグラウンドで中身を高圧縮し、アーカイブに追記して、ホット層のファイルを消す。圧縮はロックの外で行う。沈めている途中に書き込みが来たら、その回は中止する。
- **単位はリージョン（32×32 チャンク）**: 保存処理はどのチャンクがロード中かを知らないため、「最近書かれたか」で判断する。プレイヤーが離れて 10 分たった場所が沈む。

## ホット層（`.hzr`）

- 256 バイト単位で詰めて配置（`.mca` は 4096 バイト単位で、1チャンク平均約 2KB が無駄になる）。`.mcc` 別ファイルは使わない。
- 書き込み順: 空き領域に書く → 索引を更新 → 古い領域を解放。どの時点で落ちても、古い版か新しい版のどちらかが残る。
- 各レコードは座標、長さ、xxh32 チェックサム、世代番号、タイムスタンプを持つ。索引が壊れていたら、レコードを走査して作り直す（同じチャンクは世代番号の大きい方を採る）。
- 索引にもチェックサムを持たせ、中身が同じチャンクの書き込みは飛ばす（変更チャンクだけ保存）。
- 削除は「削除済み」の索引項目で表し、コールド層のコピーを隠す。

## コールド層（`.hza`）

```
ブロック 0, 1   スーパーブロック（世代番号の大きい方が有効、交互に書く）
ブロック 2〜    ストライプの列。1ストライプ = データ 16 ブロック + パリティ 2 ブロック
```

- ブロックは 4096 バイト。末尾 4 バイトは「ブロック番号と中身」の CRC32 なので、壊れたブロックはそれ自身で分かる。
- 1ストライプ 18 ブロックのうち、**どの 2 ブロックが壊れても（読めなくても）Reed–Solomon で復元できる**。容量の上乗せは 12.5%。
- データの流れ（ブロックを連ねたもの）には、チャンクレコード、辞書レコード、索引レコードが入る。
- 追記の順: ストライプを書く → fsync → スーパーブロックを書く → fsync。途中で落ちても、前のスーパーブロックが前の状態を指したまま残る。
- 辞書: 最初に沈めるとき、チャンクが十分あれば学習する（zstd の辞書学習）。辞書はアーカイブの中に保存する。
- 死んだデータ（ホット層で書き換えられたものや削除されたもの）が半分を超えたら、アーカイブを丸ごと書き直す（詰め直し）。新しいファイルに書いて、入れ替える。
- 索引には、チャンクごとの世代番号と、ホット層での形のチェックサム（変更チャンク判定用）を持つ。

## 変換・検査ツール

```sh
horizon-world convert-world <ワールド> hzr   # .mca → hzr（全部コールド層へ、検証後に .mca を消す）
horizon-world convert-world <ワールド> mca   # hzr → .mca（バニラで開ける形に戻す）
horizon-world verify <ワールド> [--repair]   # 全チャンクを検査。--repair で直せるものを直す
horizon-world world-size <ワールド>          # 形式ごとの容量
horizon-world bench-read <ワールド>          # ゲームと同じ経路で全チャンクを読む速さ
horizon-world bench-write <元ワールド> <新しいフォルダ> hzr|mca   # 保存と同じ経路で書く速さ
```

サーバーを止めてから使います。サーバー側は `horizon-storage.json` を見て自動で形式を選ぶので、設定は要りません。ホット層からコールド層への移動までの時間は、`horizon-storage.json` の `settle_after_seconds` で変えられます。

## 実測（2026-11-12、この PC の Windows 11、26.3、シード 12345）

サーバーの `/pregen start 800` で生成したワールド（12,204 チャンク、地形・エンティティ・poi の合計）です。

| 項目 | バニラ `.mca` | hzr |
| --- | --- | --- |
| 容量（全部コールド層、パリティ込み） | 117.6 MiB | **92.8 MiB（-21%）** |
| 容量（全部ホット層） | 117.6 MiB | 99.1 MiB（-16%） |
| 書き込み（保存と同じ経路、fsync 込み） | 6.7〜6.9 秒 | **1.8 秒（約3.7倍速い）** |
| 全チャンクの読み込みと NBT 解析 | 3.2〜3.6 秒 | 3.2〜3.3 秒（同等） |
| 変換（mca → hzr、読み戻し検証込み） | - | 22 秒 |

- コールド層の容量にはパリティ（12.5%）が含まれている。パリティを除いた中身は、バニラより約3割小さい。
- 読み込みの時間はほぼ NBT の解析で、保存形式による差は誤差の範囲。
- 実機テスト: hzr に変換したワールドでプラグイン入りサーバーを起動し、クライアントで入ってブロックを壊したり置いたりした。プレイヤーがいる場所はホット層に残り、テレポートで離れると、地形と poi はコールド層へ移ってホット層のファイルが消えた。スポーン付近のエンティティは毎回中身が変わるのでホット層に残った。再起動後も変更はそのまま残り、`verify` も全チャンク正常だった。

## できないこと（今のところ）

- 本家の不要チャンク削除ツール（`horizon-server prune`）や、`.mca` を前提にした外部ツール（地図ビューアなど）は、hzr のワールドを読めない。使うときは一度 `mca` に戻す。
- 地形・エンティティ・poi の3つをまとめて1回で確定する仕組みはない（バニラと同じ）。
